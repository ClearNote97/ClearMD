# Feature 003 — `.odt` converter

## Goal

A LibreOffice Writer document (`.odt`) — a report, a public-sector form, a thesis — becomes one readable
Markdown file, with its equations rendering on GitHub and Obsidian, using only the standard library and without
leaving the machine; whatever Markdown cannot hold is said, not hidden.

## Scope

- **Includes:**
  - An own converter for `.odt` with the standard library only (ADR-0006, ADR-0024), running in the worker
    process (ADR-0015), through the same pipeline, plan, limits and summary of features 001–002.
  - The supported subset below; anything else keeps its text and is reported.
  - LibreOffice Math formulas converted to LaTeX for a defined subset; the rest shown as StarMath source.
  - Conversion notes (ADR-0022) for images not extracted, formulas kept as source, comments and tracked
    changes, simplified tables and unknown parts.
  - Detection: the `.odt` extension, and magika's `odt` label for files without extension (ADR-0021); the
    archive check of feature 001 (ODT is ZIP-based).
  - The output guarantee of ADR-0023, moved to a module shared by both own converters.
  - A benchmark case, so its speed and memory factors are measured.
- **Does not include:** `.ott`, `.fodt`, `.ods`, `.odp` (another OpenDocument type is "unsupported format");
  extracting images (placeholders only); page layout (headers, footers, columns, page breaks); generated
  content (tables of contents, indexes, bibliographies: they are regenerated by the editor, so they are
  dropped); drawings and charts (placeholders); macros and forms (never run, dropped).

## The supported subset

| OpenDocument | Markdown |
|---|---|
| paragraph with the `Title` style | `# Title` |
| paragraph with the `Subtitle` style | an italic line under the title |
| `text:h` with `text:outline-level` 1–10 | headings, the shallowest level present at `##` |
| `text:p` | a paragraph |
| bold, italic, underline, strike-through (automatic or named styles, parents followed) | `**…**`, `*…*`, `<u>…</u>`, `~~…~~` |
| superscript, subscript | `<sup>…</sup>`, `<sub>…</sub>` |
| monospace text (a monospace font, or the `Source Text` style) | `` `…` `` |
| `text:list` (nested; bullet or number from its list style; `text:start-value`) | `-`, `1.` |
| `text:a` | `[text](url)` (the link rules of ADR-0023) |
| `text:note` (footnotes and endnotes) | `[^n]` with the note at the end |
| paragraphs with the `Quotations` style | `>` block quote |
| consecutive paragraphs with `Preformatted Text` / `Source Code` style | one fenced code block |
| `table:table` (header rows, or the first row) | a Markdown table |
| merged cells (`number-columns-spanned`, `covered-table-cell`) | content in the first cell, the others empty, a note |
| `draw:frame` with `draw:image` | `*Image: title*` (title, else description, else name), a note with the count |
| `draw:frame` with a LibreOffice Math object | `$…$`, or `$$…$$` alone in its paragraph (MathML subset) |
| `text:s`, `text:tab`, `text:line-break` | spaces, a space, a hard line break |
| fields (page number, date, author, cross-references) | their displayed text |
| `text:section`, `text:soft-page-break`, bookmarks, reference marks | content kept / dropped (layout only) |
| hidden text and paragraphs | dropped |
| table of contents, indexes, bibliography | dropped (generated) |
| `office:annotation` (comments), `text:tracked-changes` | dropped; the text is the final one; a note |

### The MathML subset

`mi`, `mn`, `mo`, `mtext`, `mspace`, `mrow`, `mfrac`, `msqrt`, `mroot`, `msub`, `msup`, `msubsup`, `munder`,
`mover`, `munderover` (limits and accents), `mfenced` and fence operators (`\left…\right`), `mtable` (as
`matrix`), Greek letters and the usual operators and relations mapped to their LaTeX commands. Anything else
makes the whole formula fall back to its StarMath source.

## Acceptance criteria (what MUST be true)

Each criterion has an acceptance test named after its id (`tests/acceptance/test_003_odt_converter.py`).

### Through the pipeline

- [ ] **AC-01** An `.odt` file converts through the CLI exactly like the formats of features 001–002: into
  `ClearMD_Output/OutputMD/<name>.md`, listed in `Resumen_ClearMD.md` with format `ODT`, in cost order, under
  the worker's limits.
- [ ] **AC-02** An `.odt` without extension is detected by its content (magika `odt`) and converted.
- [ ] **AC-03** The archive check of feature 001 applies: an `.odt` zip bomb is skipped before anything is read.
- [ ] **AC-04** Another OpenDocument type renamed to `.odt` (a spreadsheet) fails with "unsupported format"; an
  encrypted `.odt` fails with "password-protected"; a damaged one with "damaged file". The batch goes on.

### Structure and text

- [ ] **AC-05** Title and subtitle styles become `#` and an italic line; outline headings become headings with
  the shallowest level present at `##`.
- [ ] **AC-06** Bold, italic, underline, strike-through, superscript, subscript and monospace follow the table,
  from automatic styles, named styles and their parents.
- [ ] **AC-07** Lists (nested, bullet and numbered, with a start value), links, footnotes and endnotes, quotations
  and preformatted paragraphs follow the table.
- [ ] **AC-08** Spaces (`text:s` with a count), tabs, line breaks and fields keep the text readable; hidden text,
  generated tables of contents and layout-only elements disappear.

### Tables, images and formulas

- [ ] **AC-09** A table becomes a Markdown table with its header row; a table with merged cells keeps every cell's
  text in place and is reported as simplified.
- [ ] **AC-10** An image becomes an italic placeholder with its title or description; the note counts the images
  not extracted; nothing but the Markdown and the summary is written.
- [ ] **AC-11** A formula inside the MathML subset becomes LaTeX (`$\frac{a}{b}$`, `$x^{2}$`, `$\sqrt{x}$`,
  `$\sum_{i=1}^{n} i$`, `$\alpha$`), display math when alone in its paragraph.
- [ ] **AC-12** A formula outside the subset is shown as its StarMath source in inline code, with a note.

### Honesty

- [ ] **AC-13** Comments are removed and tracked changes resolved to the final text; a note says the document had
  them.
- [ ] **AC-14** Elements outside the subset keep their text and are listed in a note (at most 20 shown, then
  "and N more"); the exit code stays 0.
- [ ] **AC-15** Notes are shown in the user's language (EN/ES).

### Safety

- [ ] **AC-16** An XML part with a `DOCTYPE` or an entity declaration refuses the file as damaged; nothing is
  expanded.
- [ ] **AC-17** XML parts over the element, depth or character limits are refused as damaged quickly, without
  exhausting the worker; deep nesting never crashes the converter.
- [ ] **AC-18** The output guarantee of ADR-0023 holds for `.odt`: for hostile text, the Markdown holds no HTML,
  image, link or block structure the document did not write as such (checked with a CommonMark parser and a
  seeded fuzz, as for `.tex`).
- [ ] **AC-19** Object and image references point inside the archive only (`../`, absolute paths and URLs are
  never followed); formula objects over their count limit fall back to their StarMath source, and objects over
  their size limit (never read) to the formula placeholder, with a note.

### Measured

- [ ] **AC-20** The benchmark measures `.odt` (speed and memory per MiB of text parts) and `schemas/limits.py`
  uses the measured values.

## Actors and data

- **Actors:** the same as feature 001 (CLI now, GUIs later).
- **Data:** `.odt` files, read-only; only `mimetype`, `META-INF/manifest.xml`, `content.xml`, `styles.xml` and
  the `content.xml` of formula objects are read; images inside are never decompressed.

## Risks / open questions

- **No LibreOffice in the dev container:** fixtures are generated to the ODF 1.3 schema; a real file exported by
  LibreOffice (on the author's Windows machine, with no private content) should join the fixtures before the
  feature closes.
- **Style inference:** a document may fake headings with big bold paragraphs; only real headings
  (`text:h`) and the title styles become headings.
- **MathML from other editors** (Word's equations exported to ODT) may use constructs outside the subset; they
  fall back to the StarMath source when there is one, otherwise to a note.
